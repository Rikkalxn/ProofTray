# 相机、后台与图库测试：0.6.0-background-preview

目标设备：Nikon Z6 II + 小米 17 Pro Max / Android 16。计划 2026-10-29 实机验证。
0.4 版已安装，用户反馈能浏览相机预览、保存照片，但蓝牙连接有问题；具体模式与固件待记录。
0.6 已于 2026-10-29 构建，4 组 C++ 测试和 15 个 JVM 测试通过；尚未安装或实机验证，不能宣称支持整个 Z 系列。

## 已实现的代码路径

- BLE 智能设备服务发现、公开四阶段身份握手、经典蓝牙配对发现和系统配对请求、Wi-Fi 启动请求。
- AP：已有相机热点连接，或者输入 SSID / WPA2 密码后通过 Android 系统连接选择器加入热点。
- STA：绑定手机当前 Wi-Fi 网络，通过手动 IP 或 mDNS 发现结果连接相机。
- PTP/IP 双通道初始化、打开会话、设备信息、存储卡与文件目录、标准缩略图、原片下载。
- STA 主机登记：能力支持时读取配对码；用户核对并在机身确认后，显式发送确认操作。
- JPEG / NEF / NRW 的单张与筛选后批量下载。下载队列持久化，分块检查点落盘，重连重新确认文件身份。
- 分段读取优先使用标准 `0x101B`，明确不支持时尝试已报告的尼康 `0x9431` 扩展；否则重试采用整文件读取。
- 下载过程中使用 connectedDevice 前台服务；目录读取和原片接收期间持有有超时的 CPU 唤醒锁。
- 蓝牙便携 JPEG 使用 BLE 请求通知 + 独立认证的经典蓝牙 RFCOMM；默认关闭，需在设置选择控制设备与传图设备。
- GPS 通过独立 location 前台服务按需采样；优先 BLE，设备支持时复用现有 Wi-Fi。默认关闭，权限按操作申请。

## 第一轮：手动 AP

1. 相机打开“连接至智能设备”的 Wi-Fi 模式，手机先在系统 Wi-Fi 页面连接相机热点。
2. 打开 OpenBridge → 相机 → 相机热点。手机已连接热点时可直接连接；手动热点信息与高级 IP 选项按需展开。
3. 点击连接，依次观察网络、PTP/IP、目录阶段；若自动网关不正确，手动填写机身实际 IP。
4. 先下载一张小 JPEG，再下载一张 NEF，比较文件大小并用相册 / LR 打开。
5. 多选 10 张下载，尝试暂停、继续和取消；传输完成前文件保持 MediaStore pending 状态。
6. 下载中断开相机 Wi-Fi，再重连、刷新目录并点击该任务“重试 / 续传”。相机不支持分段读取时会明确重传。

JPEG 放入 `Pictures/OpenBridge`；RAW 放入 `Download/OpenBridge`，原文件保留不改写。
相机未报告可靠序列号时，使用会话级身份；为防止拼错文件，不跨会话续传这些任务。

## 第二轮：BLE 引导 AP

1. 在相机中进入“连接至智能设备 → 开始配对”，应用在“蓝牙配对”卡片点击“搜索蓝牙相机”并选择相机。
2. 完成应用身份握手后，根据机身提示点击“系统配对发现”，选择相机的经典蓝牙地址，核对系统配对码。
3. 系统配对完成后重新扫描并连接 BLE，再点击“开启相机 Wi-Fi”。
4. 使用 AP 步骤连接热点并取图。仅 GATT 已连接不代表身份验证或图像传输已完成。

当前 Wi-Fi 凭据由用户按机身显示填写；没有接入官方加密凭据的自动解密。
0.6 已加入蓝牙小图代码路径；不是纯 BLE GATT 传像素。Z6 II 上的握手、RFCOMM 方向、待传队列和暂停恢复仍需实测。
可先在设置选择两个设备地址，启用“便携 JPEG · 蓝牙”，在机身开启自动选择发送，再拍摄一张进行最小验证。

## 第三轮：STA

1. 先使用已经成功的 AP 会话，展开“高级连接选项”，尝试“首次 STA：登记当前手机”。需要设备报告相应操作能力。
2. 核对应用显示的配对码，在相机确认当前主机后，再点击应用中的完成登记。
3. 将手机和相机连接至同一路由器，选择“同一局域网”，手动输入相机当前 IP；也可以搜索局域网相机。
4. 复用同一个应用安装和主机身份重新连接，测试目录与原图下载。

不同机型 / 固件的主机登记菜单、配对码格式及 STA 接入门控可能不同。
若机身在初始化时直接拒绝连接，本版会保留 InitFail 码，不会猜测成“其他程序占用”。
某些机型没有 mDNS 广播；搜索不到时仍可手填 IP。当前不做全网段端口扫描。

## 必须确认的边界

- 新机型不能仅凭名称推断支持；需要机身固件、模式和返回的操作能力一起验证。
- 相机目录按用户选择的批次读取 ObjectInfo，每 8 项增量发布；首批不能保证整卡全局精确时间排序。
- 预览按需请求；未下载的缩略图不能当原片导出。LUT 已加入 0.4，RAW 渲染与 DNG 转换仍未实现。
- 视频入口和 USB 传输尚未接入。64 位偏移处理有协议路径，但没有大视频真机验证。
- 在同一已确认身份和同一文件元数据下续传；不自动重用旧会话的 PTP 句柄。
- 队列暂停对分段传输在块边界生效；整文件传输需等待当前文件，取消可能导致当前 PTP 会话断开。
- 关闭 / 重启应用后，未完成任务标为等待；重新连接并刷新目录后手动重试，不宣称自动后台恢复。

## 诊断

管理流程验收：

1. 在 0.4 数据上覆盖升级，确认原片、评分、导出与下载队列仍在；图库不显示远端缓存。
2. 相机导入先加载 50 项并停止；继续加载保留前批，切换每批数量后只影响后续批次。筛选按已加载范围执行。
3. 点击网格单张查看，对比标准缩略图与能力支持的大预览；断开后显式打开离线预览再查看。
4. 导入 JPEG / NEF 后，确认图库出现原片、导入页默认隐藏它们，“已导入”中仍可找到。
5. 清空选片列表，再刷新相机，确认仍能标记已导入；从图库移除后，手机文件仍能通过原 URI 读取。
6. 用不同相机、卡槽、同名但不同大小或拍摄时间的照片检查去重；未知大小不能直接消失。
7. 翻页或清理中断时重试，确认不会跳过未保存的元数据。待传输任务存在时，清理操作应提示先完成或取消。
8. 蓝牙问题单独记录扫描、连接、认证或启动 Wi-Fi 的失败阶段，再结合日志排查。

后台与位置新增验收：

1. 自动下载、GPS 均关闭，只打开图库；确认没有扫描、数据连接、定位请求或相应前台服务。
2. 读取已配对列表不应发起扫描；控制和传图序列号均可获得时，错误的跨相机关联必须被拒绝。
3. 只拍 RAW，选择蓝牙便携 JPEG：验证 JPEG 文件能打开、像素尺寸合理、RAW 未被标为已导入，实际 Wi-Fi 不应自动启用。
4. RAW+JPEG 同拍、分存双卡：时间与文件名匹配时便携副本去重，之后仍可分别导入两个原件。
5. 自动原图先建 Wi-Fi 基线：已有 800 项不应全部进队列，新拍才加入；添加卡槽、换卡事件或重新连接要重建基线。
6. 退后台与锁屏时分别测试三档；记录传输时延、手机 / 相机电量变化。未测量前不比较官方耗电水平。
7. 分块暂停后检查 CPU 唤醒锁释放；取消暂停中的任务应立即结束等待。蓝牙批次暂停应关闭数据连接，继续后检查相机待传恢复。
8. 拒绝精确位置授权不启动定位；GPS 打开而相机离线时不采样；BLE 没有位置请求时待机，手动同步可以取得一次新定位。
9. 核对新拍照片 EXIF 的经纬度、半球、海拔及 UTC；关 GPS、断连接、过期定位或精度不合格时不继续发送旧位置。
10. 验证相机繁忙、有数据中断、空间不足和权限丢失：小图重试不能拼接 RAW 偏移，导入历史只能在副本发布完成后记录。

应用错误提示保留阶段、PTP 操作码和响应码。诊断 tag 为 `OpenBridgeCamera`，不记录 Wi-Fi 密码和配对挑战内容。
带手机测试时可用 ADB 获取当前进程日志：

```powershell
. 'D:\c++\OpenBridge\tools\android-env.ps1'
$phoneProcessId = (adb shell pidof org.openbridge.app).Trim()
adb logcat --pid=$phoneProcessId -v threadtime OpenBridgeCamera:V AndroidRuntime:E '*:S'
```

先记录相机型号、固件、连接模式、应用提示和失败时的文件大小；不要仅凭“100% 后失败”认定存储空间不足。
