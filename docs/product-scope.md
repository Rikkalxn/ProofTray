# 首版范围与验证标准

2026-10-28 更新：组合筛选、连拍折叠与同步放大比较提升为 P0 基础能力，批量转换和导出加入功能范围。

## 产品定位

在相机预览中完成选片，按需取得原片，再衔接系统编辑器与 LR / PS。
功能数量不是目标：N-link 已有传输队列、格式 / 已下载筛选、RAW/JPEG 配对等能力。
差异化假设是组合条件与保存查询、离线选片、比较效率、衍生版本关联及可靠交接；需要真实使用验证。
当前不能宣称本项目比 N-link 连接更稳定、传输更快或机型兼容性更强。

## P0

- 组合筛选：文本、格式多选、评分上下限、挑选 / 淘汰、下载状态、拍摄日期、大小、机身、镜头、标签。
- 拍摄参数范围：ISO、光圈、曝光时间、焦段；横 / 竖 / 方形构图；只看 RAW/JPEG 配对项。
- 不同字段之间 AND，单字段多个枚举值之间 OR；区间包含两端；支持保存和删除查询。
- 元数据未取得是第三种状态，显示待确认数量；用户可以选择保留或排除，不能默认为零。
- 连拍折叠、展开到单帧、多选、打星和挑选标记；有明确连拍标识时优先使用。
- 时间邻近只能推测连拍，必须标记为推测；没有身份或拍摄时间时不能强行归组。
- 2–4 张并排比较、联动缩放与平移、独立查看和复位。当前采样预览不得冒充原图像素级检查。
- 批量原文件导出，包括 NEF；JPEG / PNG 转换、JPEG 质量和输出长边设置。
- 导出队列显示状态、进度、错误、结果文件，支持取消、重试、暂停后续任务。
- 相机 AP / STA、BLE 连接引导、按需原图下载及检查点恢复已进入测试版代码，尚待真机验证。

## 后续处理能力

- LUT 导入、强度与批量套用；处理队列与下载队列分开。
- RAW 渲染、无损 Mosaic DNG 转换、16 位 TIFF，分别验证格式支持、颜色与元数据。
- XMP 评分 / 关键词交接、导出版本与原始文件关联。
- BLE / STA 的机身差异和扩展机型按验证矩阵推进；USB 通道尚未接入。
- 视频原文件传输可与照片复用传输基础，但不能因照片成功就标记视频已支持。

## 从用户转述反馈提炼的验证场景

用户转述一条 N-link 3.4.0 评论：Z5 II + OPPO Reno14，STA 失败被提示其他程序占用；USB 偶发失败；
800 张卡库刷新较慢；视频传输在约 70% 或 100% 后报空间或权限错误。未取得原始日志，未独立复现。
检索时可见的上游文档版本与评论版本不同，不能用某条旧代码路径直接判定评论中的根因。

| 场景 | 设计要求 | 验证方式 |
| --- | --- | --- |
| STA / AP 连不上 | 分清网络选择、TCP、握手、事件通道、PTP 会话等阶段；错误提示只陈述已有证据 | 逐阶段超时 / 拒绝模拟，实际 Z6 II 连接日志 |
| 被误报“占用” | 只有明确响应支持该结论才这样提示；保留响应码和失败阶段 | 对比握手拒绝、未注册、无路由、会话忙等场景 |
| 800 张照片刷新 | 已有目录先显示，增量更新；先请求可见预览，高清预览按需升级 | 冷 / 热目录、800 / 5000 项，记录首屏可操作时间及请求数 |
| 精确时间排序 | 有缓存直接排序；首次缺元数据时渐进补齐，不能承诺未读取全部时间就已全局精确排序 | 混合日期、乱序句柄、两张存储卡，保持滚动锚点 |
| 刷新误触 | 显式刷新入口，选片和比较手势不触发重连或全量清空 | 多选、长按、缩放、下拉操作回归 |
| 视频到 100% 才失败 | 接收完不等于保存完成，区分写入 / 收尾；仅最终成功才显示完成 | 写入 / close / 发布阶段注入失败 |
| 大文件 | 大小、累计字节和本地偏移使用 64 位；探测相机分段读取的偏移上限 | 2 GiB / 4 GiB 边界样本，能力不支持时明确拒绝或回退 |
| 空间及权限 | 区分真实 ENOSPC、授权撤回、目标不可写、格式 / 集合不匹配、源读取失败 | 本地媒体库、SAF、外置存储、低剩余空间分别验证 |
| 临时文件占用 | 估算实际工作路径的空间需求，避免隐藏的完整中转副本 | 记录传输峰值占用，保留源文件，恢复后清理未完成输出 |

以上是待执行的验收场景，不是已完成的修复或性能承诺。相机 PTP 句柄不保证永久有效，重连恢复必须重新核对文件身份。

## 当前本地工作台的验证步骤

1. 使用系统文件选择器导入真实 JPEG、PNG 和 NEF，退出后重开，检查目录与标记是否保留。
2. 使用有 / 无 EXIF 的文件设置 ISO 和日期条件，对照待确认数量；保存筛选后重开复用。
3. 导入同一次拍摄的 RAW/JPEG 和一段连拍，检查折叠、展开、多选与单帧操作。
4. 选择 2–4 张可解码照片，测试比较、同步缩放和平移、独立模式、复位和横竖屏。
5. 批量导出原文件，再进行 JPEG / PNG 转换；检查输出文件名、尺寸、方向和原文件仍然存在。
6. 对 RAW 请求 JPEG / PNG 转换，应明确提示尚未支持，不能把预览图悄悄当原图转换。
7. 导出中取消、关闭进程、撤回目录权限，确认失败可见、未完成输出可清理、重试不覆盖已有文件。

当前 C++ 主机测试已通过，首个 Android Debug APK 已构建并通过签名检查；上述真机验收步骤仍待执行。
